II. ESP32-CAM Firmware

File: esp32cam_ble_provisioning/esp32cam_ble_provisioning.ino

1. Chức năng chính

Thành phầnChi tiết

Port 81 /streamMJPEG 5fps → Flutter UI, tối đa 1 client kết nối
Port 80 /captureJPEG snapshot → Python AI, retry 20×50ms = 1000ms
Port 80 /statusJSON {ip, fps} — health check

Camera ConfigQVGA 320×240, jpeg_quality=12, fb_count=4, CAMERA_GRAB_LATEST

2. Lỗi đã gặp và cách fix

Lỗi: cam_hal: FB-OVF — Frame Buffer Overflow ngay khi boot, trước khi có client
Fix: Ban đầu thêm drainTask để drain buffer liên tục. Nhưng chính drainTask lại chiếm hết buffer, khiến /capture timeout. Giải pháp cuối: xóa drainTask, tăng fb_count=4 để sensor và capture dùng buffer riêng.
Lỗi: jpeg_quality bị override — config khởi tạo dùng 12 nhưng sensor settings sau đó set về 8 (file lớn hơn ~40KB)
Fix: Đồng nhất cả 2 về 12: cfg.jpeg_quality = 12 và s->set_quality(s, 12)
Lỗi: fb_count=2 quá ít — stream handler giữ buffer trong lúc TCP flush, capture handler không lấy được frame → timeout
Fix: Tăng lên fb_count=4
Lỗi: max_open_sockets=1 port 81 bị tăng lên 2 để Python subscribe — ESP32 phải gửi frame 2 lần, bandwidth x2, Flutter lag nặng
Fix: Giữ max_open_sockets=1 — chỉ Flutter dùng port 81. Python dùng riêng port 80 /capture
Lỗi: Stream lag khi di chuyển ESP32 — buffer tích lũy frame cũ, Flutter hiển thị frame trễ nhiều giây
Fix: Giảm FPS từ 10→8→5, giảm jpeg_quality từ 8→12 (file nhỏ hơn), Flutter flush buffer khi vượt 128KB

III. Python AI Server

File: face_recognition_advanced.py

1. Chức năng chính

Thành phầnChi tiết
CaptureGET 192.168.1.200:80/capture mỗi 1s, timeout 5s, 1 lần duy nhất (không retry)
DetectMediaPipe FaceDetection (model 1, conf 0.5) + Haar Cascade fallback
EnhanceCLAHE trên LAB channel, tăng sáng nếu mean_L < 80
MatchCosine similarity vector 64×64 grayscale flatten, threshold = 0.78
Cooldown6s sau nhận diện → _drain_capture() vẫn gọi capture để tránh ESP32 buffer tắc
MQTT Publishresult / alert / bbox qua broker.emqx.io
Auto IPPublish home/server/ip retain khi MQTT connect → Flutter tự config
Flask REST/enroll, /delete, /members, /config, /status, /health
mDNSBroadcast _smarthome._tcp → Flutter tự discover
DatabaseSQLite members.db — id, name, role, avatar, pose1/2/3
IP Detection_get_lan_ip() — chọn IP cùng subnet /24 với ESP32, tránh nhầm hotspot

2. Lỗi đã gặp và cách fix

Lỗi: MATCH_THRESHOLD=0.55 quá thấp — cosine similarity giữa 2 mặt bất kỳ đã đạt 0.55–0.7 do background chiếm nhiều pixel → mọi mặt đều match "thịnh"
Fix: Tăng threshold lên 0.78. Thêm debug log 🔍 scores: để theo dõi score thực tế từng template.
Lỗi: Retry 3 lần khi timeout → flood ESP32 với requests liên tiếp → càng timeout thêm
Fix: Giảm còn 1 lần duy nhất, không retry. Khi fail thì sleep 0.5s rồi loop tiếp.
Lỗi: Multi-worker pipeline (3 workers + queue) — nhưng AI xử lý chỉ ~23ms/frame, 1 frame/s → W1, W2 không bao giờ được dùng, code phức tạp không cần thiết
Fix: Đơn giản hóa thành single-loop — detect + match trực tiếp trong capturer thread.
Lỗi: Trong 6s cooldown không capture → ESP32 buffer đầy → timeout lần capture tiếp theo
Fix: Thêm _drain_capture(duration) — trong cooldown vẫn gọi /capture mỗi 1s để drain buffer, bỏ response không xử lý.
Lỗi: StreamGrabber subscribe port 81 → ESP32 max 1 socket → timeout liên tục, Flutter mất stream
Fix: Xóa StreamGrabber, Python dùng lại /capture port 80 như thiết kế ban đầu.
Lỗi: member_sync_service.dart parse jsonDecode(res.body) thẳng thành List → crash vì server trả về {"members": [...]}
Fix: Extract đúng: body['members'] as List
Lỗi: BLE provisioning gửi port: 81 tới Python AI server → AI dùng nhầm port stream thay vì port capture
Fix: Sửa thành capture_port: 80

VI. Vấn Đề Còn Tồn Tại

Timeout /capture ngẫu nhiên khi Flutter đang stream:
ESP32-CAM chỉ có 1 WiFi radio — stream ~100KB/s chiếm gần hết bandwidth. /capture phải chen vào giữa các frame stream. Khi WiFi jitter hoặc Flutter đang nhận frame lớn thì timeout xảy ra.

Giảm thiểu: Giảm FPS xuống 5, không retry capture, sleep 0.5s khi fail, _drain_capture() trong cooldown.

VII. Hướng Dẫn Sử Dụng

Khởi động hệ thống

  1. Cấp nguồn ESP32-CAM → tự kết nối WiFi "AFG Studio" → IP 192.168.1.200
  2. Chạy Python: cd ESP32CAM && python -u face_recognition_advanced.py
  3. Mở Flutter app → tự discover IP qua MQTT retain hoặc mDNS
  4. Stream xuất hiện trên dashboard trong vòng 2–3 giây

Enroll khuôn mặt mới

  1. Vào tab Members → Add Member
  2. Chụp 3 pose: thẳng mặt, nghiêng trái, nghiêng phải
  3. Flutter gửi base64 image → Python detect + save template
  4. Python reload templates ngay sau enroll

Thay WiFi cho ESP32 (không cần reflash)

  1. Vào Devices → BLE WiFi Setup
  2. Scan tìm thiết bị ESP32CAM-XXXX
  3. Chọn WiFi → nhập mật khẩu → Send
  4. ESP32 tự lưu + restart, Flutter tự cập nhật IP mới
